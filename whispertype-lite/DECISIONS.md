# Murmur — Architectural & Implementation Decisions (DECISIONS.md)

This document records the foundational architectural, engineering, and dependency decisions made during the development of Murmur, including empirical findings from the Phase 0 feasibility spike.

---

| # | Decision | Status | Rationale |
|---|---|---|---|
| **D1** | **Use `sherpa-onnx` crate v1.13.8** (official k2-fsa crate) | **Accepted** | `sherpa-rs` is deprecated. The official `sherpa-onnx` crate provides direct, safe Rust bindings to the native C API, active maintenance, and built-in support for NeMo transducer models. |
| **D2** | **Use `csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8` ONNX export** | **Accepted** | Pre-quantized int8 model artifacts directly from official sherpa-onnx releases eliminate the need for Python/NeMo conversion pipelines. Verified SHA-256: `5793D0FD397C5778D2CF2126994D58E9D56B1BE7C04D13C7A15BB1B4EAFB16BF`. |
| **D3** | **CPU int8 as Primary Engine (CUDA/DirectML as optional compiled provider)** | **Accepted (Phase 0 Finding)** | Prebuilt `sherpa-onnx` (v1.13.8 shared) on Windows ships with `CPUExecutionProvider`. Empirical benchmarks show CPU int8 achieves RTF **0.0661** (763ms for 11.54s audio) and RTF **0.0732** (4.5s for 61.5s audio), beating the RTF < 0.20 budget by >2.6x. Using CPU int8 as the primary engine avoids multi-gigabyte CUDA runtime bundling (~2–4 GB) and MSVC custom CUDA toolchain dependencies while delivering sub-second response times. CUDA and DirectML providers remain architecture targets if custom ONNX runtime builds are incorporated. |
| **D4** | **Self-hosted Fonts: `Silkscreen` & `Inter`** | **Accepted** | Murmur is a 100% offline, privacy-first desktop application. No Google Fonts or CDN requests at runtime. `Silkscreen` delivers the retro-futuristic pixel-computing aesthetic for status readouts and timers; `Inter` provides high legibility for transcription bodies. |
| **D5** | **WebView2 Install Mode: `embedBootstrapper`** | **Accepted** | Balances installer size (~1.8 MB overhead) with clean-machine support without requiring manual user intervention if WebView2 is missing. |
| **D6** | **Local-Only Project (No Git Push)** | **Accepted** | Strict user constraint. All versioning and changes are strictly local to the filesystem. |
| **D7** | **Model Storage in `%APPDATA%\Murmur\models\parakeet-tdt-int8\`** | **Accepted** | Follows standard Windows application data conventions via `directories` crate, separating large model weights from application binary installations. |
| **D8** | **sherpa-onnx Dynamic/Shared Linking (`shared` feature)** | **Accepted (Phase 0 Finding)** | *Critical Spike Finding:* The prebuilt static library archive (`win-x64-static-MT-Release-lib`) was built with MSVC 2022 STL and references vectorized standard library functions (`__std_max_element_1`, `__std_find_end_1`) that fail to link under MSVC 2019. Switching to `sherpa-onnx` `shared` feature bundles `sherpa-onnx-c-api.dll` and `onnxruntime.dll` cleanly, decouples from host compiler STL versions, and eliminates DLL symbol conflicts. |
| **D9** | **Dedicated OS Thread for `WH_KEYBOARD_LL` Win32 Message Pump** | **Accepted (Phase 0 Finding)** | Win32 low-level keyboard hooks require an active message pump (`GetMessageW`/`DispatchMessageW`) on the installing thread. Spawning a dedicated background OS thread for the hook with a crossbeam event channel ensures hook callbacks return immediately (< 1 ms), preventing any keyboard input lag on the system. |
| **D10** | **Dual Text Injection: Clipboard Paste with Restore + Unicode Typing Fallback** | **Accepted** | Primary injection saves clipboard, sets text, fires `Ctrl+V` via `SendInput`, pauses 120ms, and restores original clipboard. Fallback uses `KEYEVENTF_UNICODE` `SendInput` events for applications where clipboard paste is undesirable or blocked. |
| **D11** | **Anti-Distraction Floating Overlay with Win32 Extended Styles (`WS_EX_LAYERED \| WS_EX_TRANSPARENT \| WS_EX_NOACTIVATE`)** | **Accepted** | Transparent, always-on-top, skip-taskbar HUD that passes mouse events straight through to underlying applications. Features configurable inactivity dimming (e.g. 40% opacity after 2s silence), speech brightening, multi-monitor coordinate calculation, and ultra-minimal mode. |
| **D12** | **Local SQLite Storage with Auto-Pruning & Optional Audio Archival** | **Accepted** | Embedded SQLite database (`%APPDATA%\Murmur\murmur.db`) stores transcription history with performance metrics and optional WAV audio BLOBs. Automatic pruning enforces configurable retention limits (default 100 entries), with JSON export and custom dictionary replacement. |
| **D13** | **System Tray & Background Daemon Lifecycle** | **Accepted** | Main window minimizes/hides to the system tray on close while the background thread maintains low-level keyboard hooks and audio listeners. Tray context menu provides quick status, dictation toggle, settings access, and clean exit. |
| **D14** | **3-Step First-Run Onboarding Wizard** | **Accepted** | Guides users through microphone permissions check (`ms-settings:privacy-microphone`), global hotkey configuration, and offline model integrity verification before initial dictation. |
| **D15** | **Dual Windows Packaging (NSIS + WiX MSI) with `embedBootstrapper`** | **Accepted** | Configures both NSIS (`.exe`) and WiX MSI (`.msi`) installer targets via Tauri CLI. Bundles application binary, runtime shared libraries (`onnxruntime.dll`, `onnxruntime_providers_shared.dll`, `sherpa-onnx-c-api.dll`, `sherpa-onnx-cxx-api.dll`), and embeds the WebView2 bootstrapper for automated acquisition on clean Windows 10/11 machines. |
| **D16** | **Pure Rule-Based Smart Structure Engine (Zero Additional AI Models, Preserved Parakeet Tokens)** | **Accepted** | **Problem:** Long dictations arrive as giant monolithic blocks even when natural speech contains thoughts, pauses, and lists.<br>**Architecture:** Pure CPU-based rule engine (`src-tauri/src/asr/structure.rs`) executed synchronously in the post-processing pipeline prior to text injection.<br>**No Second Model / No LLM:** Preserves 100% offline guarantee, zero additional RAM/VRAM footprint, and zero model download.<br>**Punctuation & Capitalization Preservation:** Parakeet TDT 0.6B v3 produces authoritative capitalization and punctuation (`.`, `?`, `!`). The structure engine never rewrites, paraphrases, or alters user wording; it only introduces structural whitespace (`\n\n`), list markers (`•`, `-`, `*`, `1.`), and optional list colons.<br>**Word Timestamps:** `sherpa-onnx`'s `OfflineRecognizerResult` exposes token-level timestamps (`timestamps`, `durations`), reconstructed into word spans via `build_word_spans`. When timestamps are available, inter-word silence gaps (>250ms, >600ms, >1000ms) serve as strong thought/paragraph signals; when timestamps are unavailable (or `None`), the engine gracefully degrades to punctuation and discourse transitions.<br>**List Detection & Confidence Strategy:** Detects sequential ordinal markers (`first`, `second`, `third`, `number one`, `number two`, etc.) and list introductions (`a few things`, `several things`). Requires strict monotonic sequence and at least 2 items to prevent false positives (e.g. "the first thing I noticed" remains prose). Conservative implicit list handling avoids converting general comma lists into bullets.<br>**Performance:** Benchmark latency is < 1 ms (typically 10–500 µs), well below the 10 ms target and 100 ms limit.<br>**Known Limitations:** Highly conversational, disorganized speech without clear pauses or ordinal signals will intentionally remain prose. Complex nested sub-lists are formatted as flat sequential lists. |
